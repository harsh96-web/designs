HOW WE TEST · ACCESS ABILITY 2 · p.56
How do we test accessibility?

Test early and often, with diverse users

Real people with disabilities, on their own tech and settings. Nothing else reveals the real barriers.

Test the pieces, apart and together

Switch off images, scripts, and CSS one at a time to confirm each layer stays usable on its own.

See it the way your users do

Run screen readers and low-vision simulators to experience the design, not just inspect it.

WHAT TOOLS · ACCESS ABILITY 2 · p.58
What tools can we use?

Code validators

Check that your HTML and CSS are valid and standards-compliant.

validator.w3.org

Colour Contrast Analyser

Measures contrast against WCAG, with a built-in colour-blindness simulator.

tpgi.com

WAVE

Flags many compliance issues right on the live page, in the browser.

wave.webaim.org
No tool replaces testing with real humans.
Checked against WCAG 2.2, the current standard (W3C 2023, ISO 2025).

HOW WE MAINTAIN IT · ACCESS ABILITY 2 · p.59
How do we keep it accessible?
Accessibility fades if you stop. Make upkeep part of the process, not an afterthought.
1

Talk about accessibility with stakeholders, from the start

2

Choose dev tools and frameworks that support it

3

Write a style guide that puts accessibility first

4

Auto-update navigation as the site grows

5

Give users an easy way to report issues

6

Keep testing, always with real users
